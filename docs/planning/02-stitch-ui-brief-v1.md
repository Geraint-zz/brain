# brain — Mobile-first visual architecture brief

## Direction

Create a calm, contemporary editorial-research visual system for an evidence-informed brain health platform. The intended character is clear, credible, and human rather than clinical, hype-driven, or corporate. Use the approved text wordmark “brain”; do not invent an icon, expert credential, rating system, partner mark, or claims of market leadership.

## Visual system

- Mobile-first, one-column reading flow at small widths; spacious editorial grid on desktop.
- Typography: warm, highly legible editorial serif for display headings with a neutral sans-serif reading UI; short readable line lengths.
- Color: deep ink/navy or forest foundation, muted sage/stone surfaces, restrained warm accent. Ensure accessible contrast.
- Editorial imagery is secondary to reading and must use only approved local article media or clearly labelled temporary placeholders.
- No heavy animation, auto-play, carousels, gradients that reduce legibility, faux medical dashboards, fabricated scores, or subscription forms.

## Required page patterns

1. Homepage: value proposition; practical and research paths; audience shortcuts; guide discovery; tools/reviews; research/industry; general-information boundary; Legal footer.
2. Section landing: independent introduction, Category discovery, featured/latest supported posts.
3. Category hub: parent context, topic introduction, post cards, related Category navigation.
4. Post: breadcrumb, parent links, title, Published/Updated state, long-form body, inline images, optional supported FAQ, related posts, health boundary.
5. Legal: restrained long-form reading layout for About, Privacy Policy, Terms, and User Agreement.

## Mobile and accessibility requirements

Header has a reachable menu; navigation never requires hover; touch targets are at least 44px; keyboard focus is visible; content has semantic heading order; no horizontal overflow; image alt-text placeholders are descriptive; dates are illustrative only unless supplied by the locked content package.

## V1 authority boundaries

Use only Section → Category → Post hierarchy from Skill 01. Do not show email signup, contact submission, payments, accounts, login, comments, user content, analytics, tracking, real search, API calls, or live integrations. Legal footer links are required.
